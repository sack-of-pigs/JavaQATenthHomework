# Настройка CI-конвейера (GitHub Actions) и аудит покрытия кода через JaCoCo

Важный учебный проект, знаменующий переход от локального тестирования к автоматизированной непрерывной интеграции (CI). Проект сфокусирован на развертывании пайплайна в GitHub Actions, интеграции плагина JaCoCo для анализа покрытия кода (Code Coverage) и настройке критериев качества (Quality Gate) для автоматического падения сборки при недостаточном покрытии.

## 🎯 Цели и задачи проекта
* **Внедрение CI/CD практик**: создание и конфигурация автоматического конвейера сборки в **GitHub Actions** для верификации каждого коммита на удаленном сервере.
* **Аудит покрытия (Code Coverage)**: интеграция плагина **JaCoCo** для сбора метрик о качестве тестового покрытия.
* **Настройка Quality Gate**: конфигурация плагина JaCoCo в режиме жесткого контроля — автоматическое обрушение сборки (`BUILD FAILURE`), если покрытие по счетчику веток (**BRANCH**) составляет менее **100%**.
* **Анализ отчетов и рефакторинг тестов**: чтение сгенерированных JaCoCo HTML-отчетов, локализация «слепых зон» в логике приложения и расширение тестового покрытия без изменения исходного кода сервиса.

---

## ⚙️ Пошаговый процесс реализации проекта

1. **Инициализация и Локальный запуск**:
   * Создан Maven-проект в IntelliJ IDEA, интегрированы готовые классы `StatisticsService` и `StatisticsServiceTest`.
   * Первичный запуск `mvn clean test` подтвердил полную работоспособность стартового пакета тестов.
2. **Настройка Continuous Integration**:
   * Создан публичный репозиторий на GitHub (с корректной фильтрацией через `.gitignore` для папок `.idea`, `target` и `*.iml`).
   * Развернут конфигурационный файл для GitHub Actions. Выполнен цикл `git push -> настройка CI -> git pull` для синхронизации локальной и удаленной веток.
3. **Моделирование Quality Gate (Падение сборки)**:
   * В файл `pom.xml` добавлен плагин JaCoCo с жестким правилом: падать при покрытии веток меньше 100%.
   * Выполнение команды `mvn clean verify` локально привело к **ожидаемому падению сборки (Build Failure)** из-за наличия непротестированных путей выполнения (веток условных операторов).
4. **Достижение 100% покрытия**:
   * Проведен детальный анализ сгенерированного JaCoCo отчета.
   * Тестовый класс `StatisticsServiceTest` дополнен новыми тест-кейсами для проверки всех альтернативных сценариев ветвления. Сам сервисный класс при этом остался нетронутым.
   * Повторный запуск `mvn clean verify` завершился успешно (`BUILD SUCCESS`).

* JaCoCo успешно подтвердил выполнение условий Quality Gate (100% BRANCH coverage).

## 🛠️ Стек технологий и плагины
* **Язык программирования**: Java
* **Система сборки**: Maven
* **Инструмент автоматизации CI**: GitHub Actions
* **Тестовый фреймворк**: JUnit Jupiter (JUnit 5)
* **Плагины контроля качества**:
  * `jacoco-maven-plugin` (с настроенным элементом `CHECK` по типу `BRANCH` на уровне `1.00`).
  * `maven-surefire-plugin` (для управления запуском тестов).
